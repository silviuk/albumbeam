PhotosBeam 0.3.0 — local camera timeline

Implemented:
- Explicit phone Start / refresh camera feed with Android 8+ media permissions,
  Android 13 granular media access and Android 14 partial-access support.
- Local MediaStore Images/Video collections, DCIM/Camera only, capture-date-first
  ordering and added-date fallback. No per-item file reads during catalog setup.
- Authenticated, pinned native media source with 100-entry catalog pages, strict
  same-origin catalog/thumbnail validation and bounded response reads.
- Bounded thumbnail creation and 8 MiB RAM cache; originals remain separate,
  requested with original media format and served with byte-range support.
- TV lazy grid, date headings, date browsing, loaded-day/item selection, filters,
  selected collection and slideshows. Camera photos use full-size-file TV decode.
- Original video tracks retained without conversion; no 2,000-item timeline cap.

Validation completed:
- Kotlin/Compose compilation and 84 local non-network regression tests pass,
  including timestamp fallback, time zones, folder boundaries, paging beyond
  2,000, overflow bounds, grid indices, preview bounds, origin validation and
  bounded response reads compatible with Android 8.
- Full Android unit suites, both APK builds, phone/TV lint and instrumentation
  APK compilation pass. Existing browser helper fixture checks pass.
- Android 15 / API 35 emulator instrumentation passes both camera tests:
  real MediaStore insertion/query, newest-first ordering and excluding non-camera
  files; bounded thumbnails; original JPEG byte equality; full/range reads;
  pinned HTTPS; unauthorized catalog rejection; and a 2,105-item paged timeline.
  CI: https://github.com/silviuk/albumbeam/actions/runs/42416859496
- APKs retain the original signing certificate and package IDs, use version 0.3.0
  / code 20, preserve dependency classes and resource IDs and pass 16 KiB alignment.
- Media read permissions are present only in the phone APK. Legacy storage access
  has maxSdkVersion 32; modern image/video/selected-media permissions are declared.
- Original source video data is not re-encoded. Photos are decoded to a bounded
  TV resolution; thumbnail generation is isolated from original-file delivery.
- Later changes update validation/setup text and avoid redundant CI runs when
  only release-publishing workflows change; application code is unchanged.

Not run on hardware: Samsung permission-dialog UX, partial-library grants on a
real phone, Chromecast D-pad focus, physical 4K/HDR/video playback, screen-off
sharing reliability and large real camera libraries. The emulator validates
MediaStore/server behavior, not hardware codec/display performance. Sharing is a
snapshot; refresh is explicit, and filters/day selection apply to loaded items.
