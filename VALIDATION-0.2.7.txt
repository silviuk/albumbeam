PhotosBeam 0.2.7 — readable compact TV controls and startup response reuse

Evidence:
- v0.2.6 log: Google file 604,366,239 bytes exceeds ~340 MB disk budget; first
  response discarded, another 11s header wait, ignored range to end metadata, then
  whole-file read and another reopen. First frame 91,137ms; decoder 303ms.
- The 33 MB clip was cancelled during tail preparation after ~3s, before an error.
- This is not proof of a decoder/codec limitation; server/file delivery dominates.

Changes:
- Pass the initial response to the player for oversize/206 bypass paths.
- Use explicit end offsets for known-size direct seeks; same-file bounds only.
- Propagate initial buffer failure instead of hidden extra network attempts.
- Persistent error feedback and preparation/byte progress, including low disk.
- Video sample buffering: target 48 MiB, 3–10s window, 750ms startup threshold.
- Compact actions and more direct viewer controls; three-second idle behavior.
- Explicit light text colors for both Material libraries, settings surfaces and QR.
- TV storage settings reachable from settings and viewing options.

Validation completed:
- Local Kotlin/Compose compilation and 71 non-network tests pass.
- Real TLS regression verifies oversized-response body remains readable without
  another initial request; a known-size footer request uses explicit bounds and
  a simulated range-capable server returns exactly the expected metadata bytes.
- Existing and new ownership/cancellation, cross-file range isolation, buffer and
  network failure regressions pass in the full CI suites.
- Both APK builds, full unit suites, phone/TV lint and instrumentation APK builds
  pass: https://github.com/silviuk/albumbeam/actions/runs/42411003010
- Signed APKs retain the original certificate, package IDs, version 0.2.7 (18),
  dependency classes and existing resource IDs, and pass 16 KiB alignment checks.
- Specified solid settings text/background contrast is 15.85:1; focused buttons
  12.14:1. Dark backings were strengthened over potentially bright media.
- APK production code matches the validated tree; later changes only add the real
  TLS regression and validation documentation.

Not run: physical Chromecast UI/focus review, device instrumentation tests or
Google endpoint timing with the user's private video. Google ignoring ranges and
end metadata still limit startup; bounded ranges may or may not be honored by it.
No claim of instant startup for the 604 MB cloud file is made.
